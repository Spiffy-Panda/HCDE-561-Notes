## Project Scope Discussion

The class talked through the spectrum of effort for the course project. By my standards this project lands on the simple end.

- **Simplest end:** a Claude Chat Project — drop the context files in as Project Knowledge, work in the chat. No infra, no glue code; the file-management surface inside Projects does all the lifting.
- **Hardest end mentioned:** something along the lines of an [n8n](https://n8n.io/) workflow — a self-hosted automation pipeline wiring AI into multi-step flows with triggers, branching, and external services.

Most of my existing side-projects (bioponic monitor, BT gym, Autonome) are well past either pole in complexity, so the constraint here is *staying small enough that the project is about the assignment, not about the system around it*.

## What a Personal Context File Is

Walked through what a *personal context file* actually is — a portable markdown file describing the user (role, voice, standards, anti-patterns, audience, expertise/non-expertise) that gets dropped into any AI tool to replace the generic-professional baseline with something that actually fits. See [student-guide](class-notes/session-5/handouts/student-guide) for the full framing and [example-context-file](class-notes/session-5/handouts/example-context-file) for a worked example (Maya Chen, ~700 words).

The pitch: build it once, reuse it across ChatGPT / Claude / Claude Code / Custom GPTs / etc. Lives separately from project-specific `CLAUDE.md` files — the project file is about the project; the personal file is about you, referenced from the project.

In-class exercise: pair-interview format (deliberately not solo drafting, because writing yourself onto a blank page produces flat voice and skips the obvious-to-you specifics). [interview-prompts](class-notes/session-5/handouts/interview-prompts) is the question sheet; the [ai-interviewer](class-notes/session-5/handouts/ai-interviewer) handout is the drop-in equivalent for solo runs.

## Markdown

Quick primer on markdown — why AI tooling reads/writes it more fluently than any other format, and the minimum syntax you need to recognize and produce: headings (`#`), emphasis (`**bold**` / `*italic*`), lists (`-` and `1.`), links, code fences, tables. See [markdown-primer](class-notes/session-5/handouts/markdown-primer) for the reference.

The framing was *recognition over fluency* — most AI-practice files (CLAUDE.md, AGENTS.md, system prompts, skills) are markdown, so the bar is "not be intimidated and write basic structure," not "be a markdown poweruser."
